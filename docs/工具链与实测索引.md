## 1. 环境事实与硬约束（做任何事之前必须知道）

| 事实 | 怎么验证 / 备注 |
|---|---|
| 无 root：`adb root` → `adbd cannot run as root in production builds`；`adb shell id` = `uid=2000(shell)` | 一切需要 root 的方案直接排除 |
| **shell 不能改第三方组件状态**：`pm enable/disable` → `SecurityException: Shell cannot change component state` | 组件被清单写死 `enabled=false` 时，adb 无解 |
| `cmd role add-role-holder`（+ `cmd role set-bypassing-role-qualification true`）能用，但**授予重启即失效** | `cmd role get-role-holders <role>` 复查 |
| 手机**安全锁屏**（指纹/密码）会挡住一切 UI 自动化；`wm dismiss-keyguard` 无效 | 必须我本人解锁。重启后一定回到安全锁屏 |
| `svc power stayon usb` / `settings put system screen_off_timeout` 实测**没跨重启保持**（重启后手机 Dozing） | 每轮开始先 `svc power stayon usb` + `input keyevent KEYCODE_WAKEUP`，并确认 `isKeyguardShowing` |
| 手机默认显示器**不响应** `wm user-rotation -d 0 lock 1`，也**不响应** `settings put system user_rotation 1`（Chrome 当前台也不转） | ⇒ 手机屏**做不了**车机屏方向的代理测试 |
| 车机显示器带 `FLAG_SECURE` → **截不了图**；`uiautomator dump` 也看不到它上面的界面 | 只能靠 logcat + 人眼 |
| 手机默认显示器**可以** `adb exec-out screencap -p`（实测 3200×1440 PNG 正常） | 但本会话无法看图（模型无视觉），只能做像素统计 |
| NIO 的 `QuickFreezeManager`/`BackGroundPolicy` 会**激进冻结甚至杀后台应用**（AA、OHU 都被冻过） | 缓解：`dumpsys deviceidle whitelist +<pkg>`、`am set-standby-bucket <pkg> active`、`appops set <pkg> RUN_ANY_IN_BACKGROUND allow` |
| SkyLink 白名单配置**写不了**：缓存在 `Context.getFilesDir()/settings_config.json`（私有目录，`run-as com.skyui.skylink.coreservice` → `package not an application`）；更新入口 `com.nio.base.config.ConfigUpdateReceiver` 带 `android:permission="com.skyui.netconfig.permissions.CONFIG_UPDATE"` | `/sdcard/Android/data/com.skyui.skylink.coreservice/` 里只有 `car_transfer.txt` |
| Mac 直连网络：baidu / dl.google.com / github **通**；apkmirror / apkpure / aptoide / uptodown / archive.org **不通（http=000）** | 需要下载被墙资源时走 §5.2 的代理通道 |
| 手机装了 **Clash Meta**，监听 `7890`(HTTP) `7891`(SOCKS) `9080` | `adb shell "cat /proc/net/tcp /proc/net/tcp6"` 自己看 |
| 手机只有一个桌面图标（NioPlay）；**我明确要求不要再装 NioPlay 系新应用** | 见 `AGENTS.md` |

## 2. 本会话实测的关键机制（索引；细节在主文档对应小节）

### 2.1 AA 为什么走不通（**别再投入**，§4.9 / §4.12）
- **AA 17.7.663654**：OHU 的 Self-Mode（AA≥17.4 分支）只做一件事——连 `127.0.0.1:5277`（源码 `self/launchers/SelfLauncherV17_4.kt`）。AA 会打 `GH.DHUService: Head unit connected`，紧接着 `:car` 进程拉
  `com.google.android.apps.auto.carservice.gmscorecompat.FirstActivityImpl`（该 Activity 清单写死 `android:enabled="false"`）→ `ActivityNotFoundException` → `Head unit disconnected`。
  **用 Google 官方 DHU 2.0 复现完全相同**；用 Mac 做中继让对端"变成另一台设备"也一样 ⇒ 与客户端、与 loopback 判定都无关。
- **AA 17.3.662804**：OHU 正确切到老路径（`SelfMode: AA < 17.4 detected. Starting WirelessServer on 5288 …`），AA 真连上 5288，埋点走到
  `WIRELESS_WIFI_CAR_WIFI_SETUP_INITIALIZED → WIRELESS_WIFI_SOCKET_CONNECTED → CAR_CONNECTION_CDM_REQUESTED`，然后死在 **CDM 注册车辆**：
  - 先是缺 `REQUEST_COMPANION_PROFILE_AUTOMOTIVE_PROJECTION`（`internal|role`）→ **能用 role 补上**：
    `cmd role set-bypassing-role-qualification true` + `cmd role add-role-holder android.app.role.SYSTEM_AUTOMOTIVE_PROJECTION com.google.android.projection.gearhead`
  - 补上后暴露真正死结：缺 **`REQUEST_COMPANION_SELF_MANAGED`**（`signature|privileged`）→ `pm grant` 直接回
    `Permission … is not a changeable permission type`；换 `SYSTEM_COMPANION_DEVICE_PROVIDER` 角色也被拒 →
    `IllegalStateException: Failed to register vehicle with CDM` → 连接被 reset。
  - 17.3 的 **headunit-server（5277）** 路径（Google DHU 走的）**也是同一个 CDM 失败**。
- **根因**：这台 ROM 里 **AA 只能是纯用户应用**（`pkgFlags` 无 `SYSTEM`；`/system{,ext}/{app,priv-app}`、`/product/*`、`/my_product/*` 全都没有 gearhead stub），拿不到 signature|privileged 权限 ⇒ **单机自投影无解**（与 OHU issue #994「AA isn't installed as a system app on CN ROM」一致）。
- 现状：手机上的 AA 已恢复为**我原来的 17.7.663654**（备份在 `tmp/aa177/`）。

### 2.2 `mWindowType`（2=镜像 / 6=原生级）**由车机决定**（§4.13）
- 反编译 `tmp/skylink/dec/`：赋值 setter 只有 `windowmanager/c;->E0(I)`（windowType）/ `B0(I)`（screenType）。
- **源头**：`com/ucarmd/connectly/remoteapi/n.smali:2098`
  `invoke-virtual {p1}, Lcom/databus/proto/CastScreenProto$ScreenInfo;->getWindowType()I` → 存进 `n.c`；
  手机→车机的三个发送点（`n.smali:1223 / 1343 / 1612`）**全是把 `n.c` 回显**（1612 那处对 `type=1` 的消息硬编码 2）。
- ⇒ 想拿 6，**唯一的手机侧杠杆是"让车机把我们认成它名单里的包"**（身份伪装），且**手机端无法自证**。

### 2.3 两个"绕开方向管理器"的开关（§4.14）
| 手段 | 命令 | 本会话验证到哪一步 |
|---|---|---|
| **AOSP 标准**：让显示器忽略应用请求的方向 | `wm set-ignore-orientation-request -d 90000005 1`（读：`wm get-ignore-orientation-request -d 90000005`） | 命令**在本机可用**（在 display 0 上设 1 能读回 true）。**车机屏上的效果未验证**（需要车）——这是目前最有希望的一条 |
| **NIO 私有**：跳过白名单，所有包都可"全屏" | `dumpsys window allPackagesFullscreen 1\|0` | 实机能看到 NIO 日志 `ScreenCastController dumpCommand cmd=allPackagesFullscreen, args=[…], opti=1`；代码里它设 `SkyScreenCastOrientationManagerImpl.mAllowAllPackagesFullScreen`（`isNeedLetterbox()` 只在它为 false 时才走白名单/系统应用检查）。**但调用点前有 `enforceCallerIsRoot()`**（`Binder.getCallingUid() != 0` → `SecurityException("Must be root to call SkyAMS shell commands")`）→ 很可能仅 root；执行时**没**在 logcat 看到该异常，**是否生效待车内验证** |
| 按包忽略方向（老项目遗留） | `am compat enable 265464455 <包名>`（`OVERRIDE_ANY_ORIENTATION`） | change 在本机存在（`dumpsys platform_compat \| grep 265464455`）；**Apple Music 早已被单独 override=true**；车机屏上的效果未验证 |

### 2.4 另外两个 shell 可写的旋转设置（§4.15）
- **`skyui_custom_rotation`**（Global，本机 `-1`）：`skyui-framework.jar` 的 `android.app.ActivityThreadExtImpl`（**每个 app 进程一份**）读它；**只有当显示器是 SkyLink 且 `appWidth > appHeight`（已横屏）**时，框架把"应用感知到的 display rotation"替换成这个值。写入方是 SkyLink 的 `j.smali::O(I)`（日志 `setCameraRotation`）。
- **`skylink_inject_rotation` / `skylink_inject_rotation_value`**（Global，本机 `4` / `0,10,0`）：SkyLink 的 `VirtualDisplayOrientationUtil`（`com/nio/util/virtual_display/b.smali`）用它做"方向注入"，`startInject(i)` 把状态置 4，然后**每秒**在 `arr[i]` 与 `arr[i+4]` 之间交替写 value；`arr = {"0,-10,0","10,0,0","0,10,0","-10,0,0","1,-10,0","10,1,0","1,10,0","-10,1,0"}`。语义**未完全解析**。

### 2.5 白名单匹配规则 = 伪装壳的设计条件（§4.16）
- 配置结构：`supportPkgList` = 4 个 bizType（`cross_dev_notify` / `cross_dev_app` / `cross_dev_game` / `free_window`），条目字段
  `pkgName / appName / appNameCharacters / minVer / screenType / type / immersive / support_min_window / appIcon`。
  APK 内置资产只有 **12 app + 10 game**；主文档 §4.4 那份 45 个 app 是**车机下发后缓存**的。
- 匹配：`SettingsConfig.getCastSupportAppByName(pkg)`（`remoteapi/n.smali:165`、`b.smali:442` 在用）与 `getCastSupportAppByNameAndUid(pkg, uid)`（`uid == 0x3e7(999)` 进"分身"分支）→ **按包名**，条目带 **`minVer`**（伪装壳 `versionCode` 必须 ≥ minVer，与 NioPlay 的 `-PnioCrossVer=<≥minVer>` 对得上）。
- `checkAnyDoppelganger()` **不是反伪装**，它把克隆/分身应用**加进** support list（日志 `add the cloned doppelganger app into config support list!`）⇒ 不用怕"同名被拒"。
- 伪装壳要点：包名落在名单 + `versionCode ≥ minVer` + 只留渲染目标 UI 的 launcher Activity（**别带 CarPlay/MFI/USB-accessory 全套**——上次完整拷贝就是这么把 NIO Link 弄崩的，处置是 `adb uninstall <伪装包名>` 后恢复）。

## 5. 常用操作手册（recipe）

### 5.1 用 adb 驱动手机 UI（不用碰屏幕）
```bash
adb shell input keyevent KEYCODE_WAKEUP; adb shell dumpsys window | grep -m1 isKeyguardShowing
adb shell am start -n <pkg>/<activity>
adb shell uiautomator dump /sdcard/ui.xml && python3 tools/uifind.py "启动车机服务器"
adb shell input tap <X> <Y>
```
**坑**：`uiautomator` 里带文字的节点常常**不是**可点击节点（按钮本体在父节点上）。必须找 `clickable="true"` 那个 bounds。
例：OHU 的「独立模式」按钮是 `[210,447][680,917]`，而它的文字 `独立模式` 在 `[210,932][680,1025]` —— 按文字点必然没反应。

### 5.2 让 Mac 借用手机的 Clash 代理（下载被墙的东西）
```bash
adb forward tcp:7890 tcp:7890
curl -x http://127.0.0.1:7890 -A "<浏览器UA>" https://www.apkmirror.com   # 实测 200；apkpure 403
```

### 5.3 下载被 Cloudflare 挡的 APK（走手机 Chrome，Mac 只负责拉文件）
```bash
adb forward tcp:9222 localabstract:chrome_devtools_remote
node tools/cdp_nav.js "https://www.apkmirror.com/apk/google-inc/android-auto/" 12000 "<取版本链接的表达式>"
# 找到版本页 → 下载页 → 取出 downloadButton 的 href（含 key）
node tools/cdp_nav.js "<含 key 的下载 URL>" 16000 "<任意表达式>"   # 浏览器会开始下载
adb shell ls -lt /sdcard/Download | head -3
adb pull "/sdcard/Download/<文件名>" tmp/xxx/
```
实测：APKMirror 的 AA 17.3 就是这么拿到的（`.apkm` 包，36 MB）；`.apkm` 是 ZIP，解开后是 `base.apk` + 各种 `split_config.*.apk`。

### 5.4 降级安装 AA（**`-d` 对非 debuggable 包无效，必须先卸载**）
```bash
adb uninstall com.google.android.projection.gearhead
adb install-multiple base.apk split_config.arm64_v8a.apk split_config.xxxhdpi.apk split_config.en.apk split_config.zh.apk
```

### 5.5 用 Google 官方 DHU / TCP 中继做对照实验
```bash
adb forward tcp:5277 tcp:5277
~/Library/Android/sdk/extras/google/auto/desktop-head-unit      # 2.0-mac-arm64
# 想让 AA 看到的对端变成"另一台设备"：先 adb forward --remove-all，再
python3 tools/relay.py 192.168.x.x
```

### 5.6 反编译取证三件套
```bash
apktool d -f -o dec some.apk                                    # APK → smali（全量；-s 只解资源）
~/Library/Android/sdk/build-tools/35.0.0/aapt2 dump xmltree --file AndroidManifest.xml some.apk > m.xml
# jar 里的 dex：
unzip -o -q skyui-services.jar classes.dex && \
~/Library/Android/sdk/build-tools/35.0.0/dexdump -d classes.dex > /tmp/dump.txt   # 4.9MB dex → 74MB 文本
grep -n "SkyScreenCastOrientationManagerImpl" /tmp/dump.txt
```
系统分区里的关键文件（都可读、可 pull）：`/system_ext/app/skylink/skylink.apk`、`/system/framework/{skyui-services.jar,skyui-framework.jar,nio-link-sdk.jar}`。

### 5.7 找"系统壳命令"（NIO 把很多开关挂在 dumpsys/wm 上）
```bash
adb shell cmd -l                       # 列出实现了 shell 命令的服务
adb shell wm                           # WindowManager 命令表（含 set-ignore-orientation-request）
adb shell dumpsys window <cmd> [args]  # NIO 扩展命令入口；执行时 logcat 会打 "… dumpCommand cmd=<cmd>, args=[…], opti=1"
```

### 5.8 常用日志过滤
```bash
adb logcat -s OPENHU                                  # Open Headunit
adb logcat -d | grep -E "GH\.|CAR\.SERVICE|vanagon"    # Android Auto
adb logcat -d | grep -E "BaseVirtualWindowManager|SkyScreenCastOrientationManagerImpl"   # 车机显示器/方向
adb logcat -d | grep -E "QuickFreeze|BackGroundPolicy"                                    # NIO 冻结/杀后台
```
