# 当前结论与适用边界

公开版校订日期：2026-10-19。原始记录截至 2026-10-11。本页用于处理历史文档之间的冲突；不代表在新系统版本上重新做过实车测试。

## 已证实与尚未证实

| 事项 | 当前结论 |
|---|---|
| NioPlay | CarPlay 接收实车通过；音乐界面及自动播放附加功能曾被移除；它与后来的独立 AM 助手是不同应用 |
| AM 助手 4.10.3 基线 | 用户确认 AM / Spotify 车机画面、触摸和播放正常；Wi-Fi 下保留配对恢复已验证 |
| 助手恢复能力 | 移动网络下冷启动、连续 24 小时及长期保活尚未完全验证；不宣称开机即用或永久稳定 |
| AA 单机自投影 | 17.7 卡禁用组件；17.3 卡 CDM 特权权限；本设备路线终止 |
| 白名单 | 按包名及版本等条件匹配；免 root 修改系统名单的现有路径走不通；占用包名有冲突和闪退风险 |
| 显示器 | NioPlay 实测在 90000005 横屏；跨端应用曾在 90000001 运行；必须实时查显示器，不能套用固定 ID |
| mWindowType=6 | 由车机下发；“只有 CarPlayHostActivity 能拿到 6”的旧断言没有干净复现，不作为事实 |
| 显示旋转 | 设置显示器用户旋转只对符合 SkyLink 方向策略的应用有意义；并非任意应用横屏开关 |
| wm size | 事后改车机尺寸曾导致输入映射约 2.03 倍错位，不能作为可用方案 |

## 明确作废的实验

`tools/car-orientation-test.sh` 已于 2026-10-07 作废，本公开版在脚本入口阻止执行。历史笔记仍保留试验过程，不能视作操作指南。

- 实验目标显示器选错：跨端应用实际在 90000001，而旧实验使用 90000005。
- shell 向投屏显示器启动应用被 `shouldAbortActivityStart` 拦截（code=102）。
- `dumpsys window allPackagesFullscreen` 等私有命令所在入口无调用方且需要 root。收到 dump 日志不等于命令已生效。

纠错过程见 [历史补充记录](log/未落文档的结论-补充.md)。90000005 仍可能承载 NioPlay 或天空视窗；不要把“旧实验目标选错”理解为该显示器从来不能横屏。

## 如何读历史文档

公开版 `docs/log/` 仅保留重新编写的技术摘要；原始逐时笔记、私人网络名及对话留在本地。核心文档也包含后续已被推翻的早期段落。遇到冲突时，优先参考本页以及较晚、明确包含结果的实车记录。

原始日志、截图、助手源码和部分本地工具依赖没有公开，所以部分证据只能通过记录追溯，不能从这份仓库独立重建。所有本地路径均为实验环境说明，不承诺文件已发布。
