# 借壳触发 NIO Link 与原生应用桥接

Niolink Lab 的音乐路线由两层组成：**白名单包名的入口壳**与**手机原生应用的画面/触控桥接**。

## 第一层：借白名单身份取得车机入口

现有证据表明，NIO Link 跨端应用按包名和最低版本等配置匹配。本实验的壳占用 VidHub 白名单包名 `com.oumi.utility.media.hub`，使用满足匹配条件的版本号。车机 App List 因此出现对应跨端入口，点击后进入壳的画布。

这是利用现有白名单匹配机制，不是给系统名单添加 Apple Music 或 Spotify；不意味着壳取得了 VidHub 的原始签名或厂商授权。仍然依赖已经认证的 NIO Phone 与车辆的官方连接。

实际显示器 ID 与几何需实时读取；壳曾运行在 90000001，但不能把这个数字当成跨版本固定接口。

## 第二层：承载手机中的原生应用

原版 Apple Music / Spotify 在手机的独立虚拟显示器运行。手机本地 ADB / shell 启动能力配合 scrcpy server 创建画布、编码画面并注入输入；壳通过解码显示画面，把车机点击/滑动坐标变换回该画布。

因此车机看到的是原生应用实际运行的界面，交互最终由原生应用处理。应用没有被直接跨包拉起到壳所在的车机显示器：这种直接重定向曾被系统拦截（code=102）。

画面额外经过编解码，需评估清晰度、延迟和功耗。音频由音乐应用走座舱音频链路；本画面桥接不捕获、转码或重新播放音频。Apple Music 的杜比全景声实车结论见 [音频实测](AUDIO.md)。

## 已验证与范围

Apple Music / Spotify 的画面、触摸和播放已获实车确认。白名单包名借用会与真正的 VidHub 安装冲突；未经精简的壳曾导致 NIO Link 闪退。系统升级、最低版本条件、后台保活及无线调试恢复都会影响可用性。

本仓库公开研究文档、配置与辅助工具；完整壳应用源码和安装包未发布。当前材料不构成另一品牌手机的完整接入方案。更多稳定性限制见 [验证摘要](VERIFICATION.md)。
