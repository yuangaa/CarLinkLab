## 0. 一句话架构

```
┌─ 车机画布 (display 90000001) ─────────────────────────┐
│  壳 App（包名 com.oumi.utility.media.hub，白名单空位）  │
│  ├─ 自绘车机 UI：正在播放 / 队列 / 控制                │
│  └─ MediaController ──────────────┐                  │
└────────────────────────────────────│──────────────────┘
   手机侧（后台）                     │
│  Apple Music 官方 App 原生播放（无损）│
│  media3 session: androidx.media3.session.id.com.apple.android.music
└────────────────────────────────────┘
```

- 壳占画布**合法**（白名单包名，车机列表里显示为 VidHub，已实测能上 90000001）。
- 播放**无损**（Apple Music 官方 App 本体解码），音频从车机出（已实测）。
- 控制走**系统媒体会话通道**，不碰 Apple Music 的 client 白名单。

## 1. 真机实测结论（2026-10-07 19:01，测试 App：`apps/am-browse-test/`）

### ❌ 通道B：直连 MediaBrowserService —— 连接即被拒
- 目标组件：`com.apple.android.music/.player.MediaPlaybackService`（exported=true、无权限守卫、intent-filter `android.media.browse.MediaBrowserService`——清单层面看似开放）。
- 实测：任意第三方 client `MediaBrowser.connect()` → **onConnectionFailed**。Apple Music 在**连接阶段**就按 client 白名单（基本只放 Android Auto）拒绝。
- AAIdrive 的 README 印证了同一现象（"whitelist of clients, preventing launching/browsing；once running, can be controlled"）。
- **推论：资料库浏览（歌单/曲库树）做不了。别浪费时间。**（AAIdrive 里有 `__AUTO_ROOT__` 映射，但那是给"已被 AA 放行的 client"用的，对我们无效。）

### ✅ 通道A：MediaSessionManager + 通知监听 —— 全量可用
- 条件：壳声明一个 `NotificationListenerService`（空实现即可），我授予一次"通知使用权"（adb 可用 `cmd notification allow_listener <component>` 授予；注意 `settings put secure enabled_notification_listeners` 会被系统回写剥离，**必须用 cmd**）。
- 代码路径：`MediaSessionManager.getActiveSessions(ComponentName(壳, NLService))` → 按 `packageName == "com.apple.android.music"` 匹配 → `new MediaController(context, session.sessionToken)`。
- 实测拿到的能力全集（state=PAUSED 时）：

| 能力 | 实测值 | 说明 |
|---|---|---|
| 播放状态 | state / position / speed | 完整 |
| 传输控制 | actions=`0x6ffffd` | play/pause/skip prev/next/**seek**/fast-forward/rewind/play-pause/play-from-* |
| 队列跳转 | `ACTION_SKIP_TO_QUEUE_ITEM` | **可点队列任意首直接播放** |
| 随机/重复 | `SET_SHUFFLE_MODE` / `SET_REPEAT_MODE` | 标准接口 |
| **自定义动作 ×6** | `com.apple.android.music.playback.action.*` | **喜爱 / 随机播放 / 重复播放 / 自动播放(带 extras) / 添加到资料库 / 创建电台** |
| 元数据 | title/artist/album/duration/**artUri(512×512 mzstatic)**/本地 art bitmap | 封面直接给 URL，壳自己加载即可 |
| **队列** | size=101，每项含 title/artist/封面 URL | **等于"待播清单"整页数据** |
| 会话 tag | `androidx.media3.session.id.com.apple.android.music` | media3 会话，媒体键处理 flags=7 |

- 测试工程：`apps/am-browse-test/`（手工 aapt2/javac/d8/apksigner，无 Gradle，与壳同一工具链）。测试日志：`adb logcat | grep AMBrowseTest`。

### 结论
壳的 UI 可以做到：**正在播放页（封面/标题/艺人/进度/seek）+ 控制条（播放暂停/上下曲/随机/重复/喜爱/加资料库/电台）+ 队列页（101 首带封面，可点跳）**。
做不到的：**曲库/歌单浏览**（我需在 Apple Music App 里起播一个歌单，之后一切都在壳里操作——队列 101 首基本覆盖听歌场景）。

## 3. 壳的实现要点（在现有 `apps/nio-link-shell/` 上演进）

### 3.1 组件清单
- `ShellActivity`（已存在）：白名单入口，落在 90000001 后**常驻**（v2 已验证 cast 会话随壳存活）。改造：把过渡页换成真正的车机 UI。
- `NLService : NotificationListenerService`（空实现，参考 am-browse-test 已验证的声明写法）。
- `AppleMusicSession`：封装通道A（匹配会话、注册 `MediaController.Callback` 监听 metadata/state/queue 变化、`OnActiveSessionsChangedListener` 处理 Apple Music 起播/退出）。
- UI 层：原生 View 即可（无 Gradle 工具链下别引入 Compose/媒体库封面库——封面用 artUri 直接 HttpURLConnection 下载 + LruCache；本地 art bitmap 优先）。
- 注意 **包可见性**：targetSdk≥30 需要 `<queries><package android:name="com.apple.android.music"/></queries>`（am-browse-test 已带，实测必需）。

### 3.2 关键代码骨架（Java，工具链友好）
```java
// 连接（参考 tmp/ref/AAIdrive/.../MusicSessions.kt）
MediaSessionManager msm = getSystemService(MediaSessionManager.class);
ComponentName nls = new ComponentName(this, NLService.class);
for (MediaController c : msm.getActiveSessions(nls)) {
    if ("com.apple.android.music".equals(c.getPackageName())) { am = c; break; }
}
// 监听
am.registerCallback(new MediaController.Callback() {
    public void onMetadataChanged(MediaMetadata md) { /* 刷新封面/标题/时长 */ }
    public void onPlaybackStateChanged(PlaybackState st) { /* 刷新按钮/进度/自定义动作 */ }
    public void onQueueChanged(List<MediaSession.QueueItem> q) { /* 刷新队列页 */ }
});
// 控制（TransportControls 全量可用）
am.getTransportControls().play();            // pause/skipToNext/skipToPrevious
am.getTransportControls().seekTo(pos);       // 进度条拖动
am.getTransportControls().skipToQueueItem(qid);   // 队列点跳
am.getTransportControls().setShuffleMode(PlaybackState.SHUFFLE_MODE_ALL);
am.getTransportControls().setRepeatMode(PlaybackState.REPEAT_MODE_ALL);
// 自定义动作（喜爱/加资料库/电台…）——action id 见 §1 表
am.getTransportControls().sendCustomAction(
    "com.apple.android.music.playback.action.FAVORITE", null);
```

### 3.3 车机 UI 蓝图（照 Cider/Musish 拆，按 AAIdrive 的车机信息架构排）
- **正在播放页（默认）**：左 60% 大封面（artUri 512×512 足够），右侧标题（超长滚动，参考 `TextScroller.kt`）/艺人/专辑 + 进度条（可拖 seek）+ 控制排（喜爱｜上一曲｜播放暂停｜下一曲｜随机｜重复）+ 副排（加资料库｜电台｜自动播放）。
- **队列页**：右滑或按钮进入；列表项 = 封面缩略图+标题+艺人（数据全有）；点击 → `skipToQueueItem`。
- **横屏**：画布 1728×1616@320dpi（跨端窗口实测几何），按 ~5.4:5 设计，不必 16:9。
- 字体/触控目标按车机：最小触控 48dp，远离边缘。

### 3.4 保活与坑（平台实测约束）
- **QuickFreezeManager**：后台 3s 级冻结。壳在车机画布是前台（该显示器的前台任务），不受影响；**Apple Music 播放态有 FGS（MediaPlaybackService, foregroundServiceType=mediaPlayback）不受影响**。暂停太久被杀 → 会话从 getActiveSessions 消失，UI 显示"请在 Apple Music 起播"。
- 音频路由已实测走车机；**无需**在壳里做音频焦点（别抢，Apple Music 自己持有）。
- 别在壳里 startActivity Apple Music（会被 ScreenCastController 拦 code=102）——壳只做"遥控"，我起播在手机端完成。若想要"壳一键拉起 Apple Music（到手机屏）"，可以 startActivity 不带 displayId（落到 display 0，合法），值得验证但不阻塞主线。
- 通知监听授权：`cmd notification allow_listener com.oumi.utility.media.hub/com.oumi.utility.media.hub.MediaListenerService`（注意：当前已装壳的历史版本里**已存在** MediaListenerService 且已在授权列表——装新版壳时保留该类名可免重新授权）。
